======================================================================
1. EXECUTIVE SUMMARY
======================================================================
The main agency surfaces now use the approved Chelth language, composed from
the S2 primitives plus one shared addition (Panel / PanelLink, the P2/P4
titled card). The surfaces are:
  - Operations Overview (P2);
  - Shifts and shift record;
  - Workforce and worker record;
  - Facilities and facility record;
  - Attendance (list, record, evidence);
  - Timesheets (list, record);
  - Compliance and credential review;
  - Operations.

The Overview answers what needs attention, what is happening today and what
is coming up, using only existing queries gated exactly like their own pages.
There are no charts, trends, forecasts or scores.

Shifts, Workforce and Facilities each gained:
  - real-count quick filters (KPI cards that set URL filters);
  - a labelled FilterBar;
  - a DataTable;
  - the modal Details drawer.
Each record page gained a P4 identity header and an in-page section list that
only lists sections that render for the viewer.

No database, migration, RLS, capability, Server Action, RPC, query, workflow
or rule changed. Every existing E2E test passes unmodified.

One latent UI bug was found and fixed: GET filter forms showed stale values
after client-side navigation (§16).

3. OPERATIONS OVERVIEW
======================================================================
Route: /app/organisations/[id] (Overview).

The dashboard renders for agency workspace staff in
_components/agency-operations-overview.tsx. The h1 stays the organisation
name, with the supporting line "What needs attention, what is happening
today and what is coming up."

KPI cards ("Operations summary"). Each card appears only when its source is
allowed:

  Card                           Source and gate                     Links to
  -----------------------------  ----------------------------------  ---------------------------
  Open shifts                    listAgencyShifts(open, from today)  Shifts, pre-filtered
                                 + count not fully staffed;
                                 shift.view held
  Assignments needing attention  listAssignmentIssues + urgent       Operations
                                 count; assignment.view AND
                                 compliance.view granted, as on
                                 Operations
  Attendance to review today     listAgencyAttendance(today)         Attendance
                                 needs-review count +
                                 listOpenExceptions;
                                 attendance.view held
  Timesheets to approve          listAgencyTimesheets(submitted) +   Timesheets?status=submitted
                                 discrepancy count;
                                 timesheet.view held

Panels:
  - Today's schedule: table of today's accepted assignments (worker,
    facility, time, attendance status chip), 8 rows, then "Showing 8 of N".
  - Upcoming open shifts: facility / discipline, date, time, staffing chip.
  - Needs attention: top 5 assignment issues with a severity chip.
  - Workforce: worker records by status (real counts) with status chips.
    This replaces the reference's "readiness donut".

Omitted, because Chelth has no backing data for them:
  - Credential Expirations bars;
  - the Coverage Activity chart;
  - the date-range control;
  - the readiness donut.

Kept below the dashboard: member administration, invitations, recent activity
and self-service links.

Facility Overviews are unchanged (S4).

client-side navigation that changes the query (a quick-filter link), they

DESIGN_SYSTEM.md.

development came from my changes and were fixed in the product, not the
tests:

20. KNOWN VISUAL DIFFERENCES
======================================================================
1. The drawer is modal (locked decision 1), not docked beside a contracted
   table.
2. Overview: no Credential Expirations bars, Coverage Activity chart, date
   range picker or readiness donut (no backing data). Workforce status counts
   replace the donut.
3. No global search, notification bell, Reports, Settings or agency
   Credentials register (F6, F10).
4. No checkboxes or bulk actions, avatars or photos, kebab menus or
   numbered pagination (no product equivalents; actions stay visible).
5. Worker record: no Availability card, skills tags, Message button or "More"
   menu. The section row is an in-page list of real sections, not 8 tabs.
6. Shifts: no List/Calendar toggle. P3-C (calendar) is not supported by the
   current list query's pagination model.
7. KPI cards show no deltas ("↑ 6 from last month"). On phones they stack one
   per row, which uses vertical space; a 2-column compact phone layout is a
   possible refinement.
8. Panel header actions wrap under the description in narrow panels.
9. Record pages keep long forms (manage, edit, requirement forms) inline in
   Panels rather than in modal editors.
10. Attendance list correction cards sit as bordered cards inside the panel
    (nested borders).
