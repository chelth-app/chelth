P0-E9-3H — RATE & PRICING UX CLARITY
====================================
CHELTH — Healthcare Workforce Operations

Branch: p0-e8-visual-implementation. Presentation and copy only. Nothing
deployed.


1. CONFUSION REPRODUCED
-----------------------
Rates → a draft rate card → Rate Details (drawer):
- The header chip read "Draft". The Overview showed "v1 · Draft" and, as the
  primary note, "No rate in force today" (warning). It said nothing about
  the draft being the cause.
- The only Activate control was inside the Versions tab (Versions table →
  "Activate"), so an operator who stayed on the Overview had no visible next
  action.
- Elsewhere:
  - "Rounding and Overtime" sat directly under the rate cards with its own
    "Active" badges, which read as "the rate card is active";
  - the Draft Versions KPI said "Waiting to be activated";
  - Pricing explained matching with "No fallback to a broader rate";
  - status words mixed "Current", "Upcoming", "Starts later", "Not in force"
    and "in force".


2. RATE ACTIVATION WORKFLOW AUDIT (unchanged)
---------------------------------------------
- Server action: activateVersionAction (src/features/pricing/actions.ts)
  → RPC public.activate_rate_version.
  - rates.manage, which is privileged (AAL2; AAL1 ⇒ CH402 step-up);
  - only a draft can be activated;
  - overlapping active periods are refused (CHM12), invalid periods
    rejected;
  - audited.
- UI: InlineActionForm, which shows the normalised error under its button
  (permission, step-up, overlap, validation) — never a silent no-op.
- The Versions tab keeps Activate / Discard / New version unchanged.
- No new activation code path was added: the Overview and the table row
  render the same InlineActionForm with the same action and fields
  { organisationId, versionId }.


3. OVERVIEW ACTIVATION SURFACING
--------------------------------
Rate Details → Overview now leads with a "Status" section (status card),
then Rate Details, then Matching Rule.
- The status is derived by rateStatusCard()
  (rates/_components/rate-card-summary.ts, pure, unit-tested) from the
  card's versions — the same phase rules as before.
- Draft: primary [Activate rate]. It is full width on phones (44 px), so
  it is easy to tap and sits directly under the explanation, not below a
  blank area.
- Active / scheduled with a further draft: a secondary
  "Draft vN (from <date>) is not active yet. [Activate vN]".
- Activate appears only when the caller holds rates.manage (granted). The
  database re-checks on submit.
- Rates table: a draft row also shows a compact outline "Activate" under
  its Draft chip (rates.manage only), with the accessible name
  "Activate rate: <scope>". The ⋮ control still opens Rate Details; the row
  is not otherwise changed.
- Mobile drawer: tabs, the CTA and View Pricing Queue (still secondary, at
  the bottom) are unchanged in structure. Checked at 412 px and 1280 px
  (screenshots); no page overflow (E2E).


4. STATE-SPECIFIC COPY
----------------------
Draft:
- Title: "Rate not active yet"
- Body: "This rate is still a draft. Activate it before Chelth can use it
  for pricing."
- Action: [Activate rate]

Active:
- Title: "Rate active"
- Body: "This rate is currently available for matching shifts and
  timesheets."
- Secondary when a later version is scheduled: "A new version is scheduled
  to start on <date>. The current version remains in force until then."

Scheduled (activated, future):
- Title: "Rate scheduled"
- Body: "This rate will start on <date>."
- Secondary: "No rate is active for this matching level until <date>."
- No Activate action.

Ended:
- Title: "Rate ended"
- Body: "This rate stopped being active on <date>."
- Secondary: the review line below.

No applicable version (never activated, or discarded):
- Title: "No active rate"
- Body: "There is no active rate for this matching level on the selected
  work date."
- Secondary: "Timesheets that require this rate will wait for review until
  an applicable rate is active."

"No rate in force today" is no longer used anywhere as the primary draft
explanation.

Each state has its own glyph and title text, so meaning is never carried by
colour alone. The group is labelled "Rate status: <title>".

Vocabulary (operator-facing):
- versions: Draft · Active · Scheduled · Ended · Replaced · Discarded;
- cards: Draft · Active · Scheduled · Ended · No active rate.
- "in force" remains only in secondary explanations ("The current version
  remains in force until then").


5. MATCHING-RULE CLARIFICATION
------------------------------
Rate Details → "Matching Rule" section:
- "Matching rule: Level N · <level>", with the level wording
  "Facility + discipline + shift type" (the engine's order is unchanged;
  RATE_PRECEDENCE_LABELS now uses shift-type wording in the same order).
- Note "Exact rate required": "When a specific rate card matches the shift,
  Chelth uses an active version from that card. If none is active for the
  work date, the timesheet waits for review instead of using a
  less-specific rate. Priced timesheets keep the rates they were priced
  with."
- No "fallback", "tier", "precedence resolution" or "lookup failure"
  wording reaches the operator.


6. RATES PAGE — POLICY RENAME AND RATE / POLICY DISTINCTION
-----------------------------------------------------------
- "Rounding and Overtime" → "Time & Overtime Policies". Intro: "Choose how
  worked time is calculated for pricing and when overtime applies. These
  policies are separate from your rate cards." Secondary: "Exact minutes
  prices the recorded worked time without rounding. Overtime rules are
  applied separately for pay and bill. Policy versions take effect from
  their start date; an 'Active' policy here is not a rate card." The
  legal-advice sentence was removed from this intro.
- "Current Rate Cards" gains: "Rate cards set the hourly pay and bill
  amounts for a facility, discipline and shift type. Each card has
  versions: a draft is not used until it is activated."
- KPI copy (structure and counts unchanged):
  - Active Rate Cards: "Active today";
  - Needs Attention: "No active rate today";
  - Draft Versions: "Not active for pricing" / "Activate a version before
    Chelth can use it";
  - Upcoming Changes: unchanged.
- Status filter labels: "Active", "Needs attention (no active rate)".


7. PRICING PAGE EXPLANATION
---------------------------
"How Rates Are Matched": the hierarchy is unchanged (4 levels, same
order, same counts).
- Body: "For each worked shift, Chelth checks these levels in order. The
  first matching rate card determines which rate card must supply an
  active version." It no longer suggests falling through to level 2 when
  level 1 exists.
- Note "Exact rate required": "Once a matching rate card is found, Chelth
  requires an active version from that card for the work date. If none is
  active, the timesheet waits in Needs Attention instead of using a
  less-specific rate. Priced timesheets keep the rates they were priced
  with."
- KPI supporting copy (labels, counts and queries unchanged):
  - Needs Attention: "Cannot be priced yet";
  - Ready for Pricing: "Approved work waiting to be priced" (footer "Locked
    after approval");
  - Priced: "Pricing snapshot created";
  - Rate Cards in Force: "Active today · of N", footer "N with no active
    rate".
- An intermediate, longer footer caused page-level horizontal overflow at
  one width. It was caught by the existing pricing E2E overflow guard and
  shortened before completion.


8. PERMISSIONS
--------------
- Activate is rendered only for rates.manage = granted.
- A holder pending step-up sees the existing step-up notice on Rates, not
  the action.
- rates.view-only roles (e.g. agency operations manager) see the full
  state and copy but no Activate, in the row or the drawer (E2E).
- The RPC re-checks rates.manage + AAL2 on every submit. Errors are shown
  next to the button by the existing form.
