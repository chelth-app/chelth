4. PROJECT ARCHITECTURE
--------------------------------------------------------------------------------
- Server-first App Router. Only three client components exist: Dialog, the
  route error boundaries, and the design-system dialog demo.
- Routes are thin; business logic will live in src/features/<domain> with a
  public index.ts per feature (convention documented in
  src/features/README.md; cross-feature deep imports are lint errors).
- Every route renders dynamically (connection() in root layout) because the
  CSP nonce is per request.
- Mutation pattern for later stages: parseInput → requireAuthIdentity →
  authorise → mutate (RPC for sensitive transitions) → ActionResult.
- Lint-enforced boundaries: no process.env outside src/config; no
  service-role identifiers; no direct supabase createClient; no any /
  ts-ignore / non-null assertions / floating promises / console /
  dangerouslySetInnerHTML. Verified by a probe file that triggered all 7
  guard rules before being deleted.
Full detail: docs/architecture/TECHNICAL_ARCHITECTURE.md, PROJECT_STRUCTURE.md.

5. SUPABASE ARCHITECTURE
--------------------------------------------------------------------------------
Clients (all act as the signed-in user with the anon key; RLS always applies):
  browser.ts  Client Components   guarded by `client-only`
  server.ts   RSC/Actions/Routes  guarded by `server-only`, per-request client
  proxy.ts    session refresh in src/proxy.ts via getClaims(); forwards
              refreshed cookies to RSC and response; applies @supabase/ssr
              no-cache headers when auth cookies are set
Privileged access: none. src/lib/supabase/README.md defines the approval path
(ADR, dedicated server-only module exposing narrow functions, prefer
security-definer RPC or Edge Function). No generic admin client.

Auth foundation (identity only — roles/membership are P0-E3-S2):
  - lib/auth/session.ts: getAuthIdentity()/requireAuthIdentity() via getUser();
    returns {userId, email, emailVerified} only.
  - /auth/confirm route handler: verifyOtp for allow-listed email link types
    (signup, email, recovery, email_change); `next` restricted to same-origin
    paths; failures redirect to /auth/error with a safe message.
  - config.toml: email confirmation ON, secure password change ON, password
    >= 12 chars with lower/upper/digit (mirrored in Zod), anonymous sign-in
    OFF, no OAuth providers (Facebook will not be enabled), TOTP MFA enrol/
    verify ON, email resend throttle 60s.

Local stack: project_id "chelth"; ports 553xx (API 55321, DB 55322, Studio
55323, Mailpit 55324) — other local Supabase stacks on this machine use 543xx
and were not touched. Local analytics/vector, S3 protocol and vector buckets
disabled (not needed; analytics failed health checks locally).

Migrations: one — 20260929232049_security_baseline.sql. It creates no tables.
It revokes default privileges on tables/sequences/functions in `public` from
anon/authenticated, revokes the global PUBLIC EXECUTE default for functions
created by the migration role, and revokes CREATE on schema public from PUBLIC.

Database types generated to src/types/database.types.ts; CI fails if they
drift from the migrated schema.

7. SECURITY BASELINE
--------------------------------------------------------------------------------
- SECURITY_INVARIANTS.md: all 15 required invariants, each with current
  enforcement and what later stages must add; plus auth/authz separation,
  input, logging, headers and auth-config rules.
- Headers (next.config.ts): X-Content-Type-Options nosniff, Referrer-Policy
  strict-origin-when-cross-origin, X-Frame-Options DENY, Permissions-Policy
  (geolocation=(self) retained for the worker PWA; camera/mic/payment/USB etc.
  disabled), COOP same-origin, CORP same-origin, X-DNS-Prefetch-Control off,
  HSTS max-age=63072000 (production builds). x-powered-by removed.
- CSP (src/proxy.ts): per-request 128-bit nonce; script-src 'self' nonce
  'strict-dynamic'; style-src 'self' nonce; connect-src self + Supabase
  (https/wss); frame-ancestors 'none'; object-src 'none'; base-uri/form-action
  'self'; upgrade-insecure-requests.
  Production: NO 'unsafe-inline', NO 'unsafe-eval' — verified by E2E (zero
  console CSP violations; unique nonce per request).
  Documented DEVELOPMENT-ONLY relaxations: 'unsafe-eval' (React dev tooling),
  ws: (HMR), style-src 'unsafe-inline' (Next dev overlay injects un-nonced
  styles — discovered via dev-mode E2E run; nonce omitted in dev because
  browsers ignore 'unsafe-inline' when a nonce is present).
- Error model: AppError with stable codes across 7 kinds; toPublicError is
  the only client-facing shape; normalizeError maps SQLSTATE / PostgREST /
  HTTP status (incl. Chelth RPC convention SQLSTATE class CH4xx) and defaults
  to INTERNAL; tests prove DB messages/PII never reach public output.
- Logging: structured, level-filtered, redacting logger with pluggable sinks;
  key-based redaction (credentials, tokens, contact details, identifiers,
  documents, health, location) + string scrubbing (JWTs, bearer tokens,
  Supabase keys, emails). onRequestError logs route metadata + digest only.
- Database: pgTAP proves every public table has RLS, anon has no table
  grants, SECURITY DEFINER functions pin search_path, no public buckets, and
  new tables/sequences/functions are not accessible to anon/authenticated.
  The first test run FAILED the two function-execute checks: per-schema
  default-privilege revokes cannot remove Postgres's global PUBLIC EXECUTE
  default. The migration was amended (it had never been applied anywhere
  shared) to add a global revoke for the migration role; all 9 tests pass.
- Source maps: productionBrowserSourceMaps=false; bundle scan fails on any
  published .map.
