1. EXECUTIVE SUMMARY
======================================================================
The facility workspace now uses the same shell, primitives and patterns as
Agency, with no facility-specific design system. Facility Admin, Scheduler and
Supervisor share one shell; their differences come only from capabilities
(shift.view, shift.request, timesheet.facility_signoff, membership.*), never
from role names.

Implemented:
  - a facility P2 Overview (from the facility's own projections only);
  - Staffing Requests:
      - real-count quick filters;
      - a URL-backed filter;
      - a DataTable;
      - a facility-safe drawer;
  - Staffing Request record (P4);
  - Timesheet sign-off:
      - quick filters;
      - a state filter;
      - a facility-safe entry drawer;
  - facility attendance on the shared table primitives (same narrow
    projection);
  - member and admin surfaces in P6 card language.

No database, migration, RLS, capability, Server Action, query function, RPC,
rule, projection or tenancy behaviour changed. No data is shown beyond what
the facility already saw (§16).

3. FACILITY OVERVIEW
======================================================================
Implemented in _components/facility-operations-overview.tsx. It renders on
/app/organisations/[facility id] for facility workspace staff, under the
existing header ("Your staffing requests, who is expected and the timesheets
waiting for sign-off").

Data, each gated as on its own page:

  Source                                        Gate                   Audit
  --------------------------------------------  ---------------------  ---------------------
  list_facility_shifts (the facility shift      shift.view held        not audited
  projection: counts, agency, location,
  discipline, times, status, fill)
  list_facility_timesheet_entries (the          timesheet.facility_    audited, de-duplicated
  facility's own sign-off entries)              signoff granted        (record_audit_event_
                                                                       once), the same read
                                                                       the sign-off page
                                                                       makes

KPI cards ("Facility summary"):
  - Awaiting agency (requests not yet opened), linking to filtered requests;
  - Open requests (with "N not fully staffed"), linking to filtered
    requests;
  - Workers expected today: the sum of accepted workers on today's open
    shifts, using the facility's local date. A static figure: counts only,
    no names;
  - Timesheets to sign off, linking to the pending sign-off filter.

Panels:
  - Today and upcoming: requests and shifts, earliest first, with status
    and staffing;
  - Awaiting sign-off: up to 5 pending entries (worker, agency, date,
    worked time). This is the same facility projection as the sign-off
    page.

Deliberately NOT on the Overview:
  - Worker names per request and attendance. Those projections
    (list_facility_shift_assignments, list_facility_shift_attendance) are
    audited on EVERY call, so a dashboard visit would write one audit event
    per shift. They stay on each request record.
  - Agency assignment issues, pay, pricing, finance, coordinates, audit
    internals.

Below the dashboard (unchanged content, Panel language):
  - Agency relationships (status chips);
  - shared readiness (the existing shared projection);
  - Members;
  - Invitations;
  - Recent activity.

7. STAFFING REQUESTS
======================================================================
PageHeader: back link, copy, and a "New request" link to the existing form
(only with shift.request and request options).

Quick filters ("Upcoming requests"):
  - Awaiting agency;
  - Open (with "N not fully staffed");
  - Workers confirmed (static total of accepted workers on upcoming open
    shifts).
They are computed from list_facility_shifts. Awaiting agency and Open set
?status=…&when=upcoming and show as active.

FilterBar ("Filter requests"): Status (shift statuses) and When (Any time /
Upcoming), with "Clear filters".
  - Filtering is a display filter over the facility shift projection the
    page already loads for the counts.
  - Unfiltered, the list keeps its cursor pagination ("Older requests").
  - The bar is keyed on the URL state (the S3 rule).

DataTable ("Staffing requests table"):
  - request link (same text as before: agency · discipline · date);
  - location and time;
  - status chip;
  - staffing (fill chip or "N needed");
  - source label;
  - Details.

Empty states: "No requests yet." and "No requests match.".

The request form (Request staff) and its "not available yet" guidance
(now an EmptyState) are unchanged.

No bulk operations and no messaging.

8. STAFFING REQUEST DETAIL / DRAWER
======================================================================
Drawer (projection fields only):
  - status;
  - staffing;
  - workers needed (confirmed count);
  - agency, location, time, timezone, source;
  - agency relationship;
  - reference;
  - cancellation.
It shows no worker names (those are the audited per-request projection),
with a pointer to the request page and "Open request".

Record (P4):
  - Title: discipline · date. Description: agency · location.
  - Header chips: status, fill, and "Agency relationship not active" when
    applicable. Each appears once (E2E reads them).
  - Details: KeyValueList (agency, location, time, timezone, workers needed,
    reference, instructions, cancellation) plus Withdraw request
    (shift.request).
  - Who is coming: a table of the facility-safe projection (worker display
    name, discipline, assignment status chip, readiness chip). The region
    name "Who is coming" is unchanged. Empty state: "No workers assigned
    yet.".
  - Attendance (unchanged rule: after the shift starts, attendance.view):
    a DataTable with clock state and in/out times. The location RESULT
    label ("Inside site area") is now a neutral chip, exactly as before;
    there are no coordinates.

20. KNOWN VISUAL DIFFERENCES
======================================================================
1. The drawer is modal (locked), not docked.
2. No checkboxes or bulk actions, kebab menus, numbered pagination,
   Find Workers, Contact Facility or Edit Request (no product
   equivalents). Requirements chips, the Coverage bar and suggested
   workers are not in the facility projection.
3. The facility Overview has no attendance aggregate, no charts and no
   date range. Worker names and attendance stay per request (audited
   reads).
4. "Workers expected today" is a count only (no names on the Overview).
5. Request drawer: no worker list (audited projection), and a pointer to
   the record instead.
6. The request record's attendance section appears only after the shift
   starts (unchanged rule).
7. Inside the Agency relationships panel, the relationship list and the
   shared-readiness lists keep their bordered list style (nested borders).
8. On phones, KPI cards stack one per row (as in S3).
