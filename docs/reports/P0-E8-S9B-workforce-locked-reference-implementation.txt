4. KPI / SUMMARY AREA (real counts, same visual slots)
------------------------------------------------------
- Available Now → Active: active workers "of N workers". Links to
  ?status=active, the existing filter shortcut, and shows its active state.
- On Assignment → On Assignment: workers with an assigned or accepted shift
  in progress now.
- Needs Attention → Needs Attention: readiness not ready, or an expiring
  requirement.
- Credential Ready → Credential Ready: readiness ready with nothing
  expiring.

Readiness cards appear only with COMPLIANCE_VIEW. The group keeps its
accessible name "Workers by status".


5. FILTERS
----------
- Only the existing status filter exists. It is a native GET form "Filter
  workers" with an "All statuses" select (244 x 46 at the reference's
  first-slot width), "Apply filters", and "Clear filters" when active.
- Role, availability, credential status, facility and search filters do not
  exist in the product and were not invented.


6. WORKFORCE TABLE
------------------
- Frosted table card with a tinted 47 px header band, 60 px rows, hairline
  dividers and the reference column proportions.

Columns:
- Name: an initials avatar (36 px) and the name, linking to the worker
  record.
- Role: the assigned discipline, short code (for example CNA); "+n" when
  more.
- Reference (the reference "Contact" slot): the worker reference. Chelth
  holds no phone or email for workers.
- Today (the reference "Availability" slot):
  - "On shift" for an assignment in progress;
  - "Scheduled" for a shift starting today in its facility timezone;
  - "—" otherwise.
- Current Assignment: the facility and unit of the in-progress shift.
- Credentials: live readiness (Ready / Action required / Not eligible), or
  "Expires in N days" from an EXPIRING_SOON requirement.
- Next Shift: the earliest upcoming assignment (date and local time range).
- Status: worker status (Active / Onboarding / Inactive / Suspended /
  Terminated).
- ⋮: opens Professional Details ("Details for {name}").

Behaviour:
- Pagination: ten per page as in the reference, over the already-loaded
  list. Page links keep the status filter. The footer reads "Showing a–b of
  N professionals".
- The selected row (drawer open) is tinted with a 3 px teal accent.
- No checkbox column: there are no bulk actions.

Data comes from the worker record's own loaders and gates:
- getReadiness (COMPLIANCE_VIEW) and listWorkerDisciplines;
- listAgencyShifts (SHIFT_VIEW) plus the shift record's
  listShiftAssignments (ASSIGNMENT_VIEW) for staffed shifts in a 30-day
  window.


7. WORKER IDENTITY TREATMENT
---------------------------
- There are no worker photos in Chelth. The table uses 36 px initials
  avatars and the drawer an 84 px one, in the same geometry as the
  reference's photos.
- The name is a link to the authoritative worker record.


8. STATUS / READINESS
---------------------
Existing vocabulary only:
- worker status labels and tones (as WorkerStatusBadge);
- READINESS_LABELS;
- COMPLIANCE_REASON_LABELS in the drawer.

No "Available" or "Limited" states: availability does not exist.


9. DETAIL DRAWER (Professional Details)
---------------------------------------
- Geometry: a modal dialog, docked (no dim) at 1536 px and wider, with the
  page contracting beside it; a full-height sheet on phones. 387 px wide,
  178 px from the top, 18 px radius, 64 px header with the close button.
- Identity: an 84 px avatar, the name (Manrope 21 / 700), a status chip,
  disciplines and the reference. Start and end dates are shown as icon
  rows in the reference's contact-row slot.
- Tab row: four-column geometry with "Overview" (the populated tab).
  Credentials, Assignments and Activity are not faked; the worker record
  holds those sections.
- Sections:
  - Status;
  - Current Assignment (a real shift line, or "No active assignment");
  - Upcoming Shifts (n) with up to two;
  - Credentials: readiness items with COMPLIANCE_REASON_LABELS chips and
    "View all", which goes to the record's #readiness-heading.
- Actions:
  - primary "Open worker record";
  - secondary "View credentials" (record #credentials-heading).
  "Assign to Shift" is not offered: assignment happens from a shift record,
  and Chelth has no worker → shift flow. "Message" is not offered: there is
  no messaging infrastructure.
- Every row opens its own worker. Escape closes; focus returns to the row
  trigger.


10. RESPONSIVE BEHAVIOUR
------------------------

  spec asserts this at every width).
- Summary cards go 2-up below xl. The table scrolls inside its labelled
  region (min-width 1040).
- The drawer becomes a full-height sheet below sm. Below lg the shell uses
  the existing overlay navigation.


11. FUNCTIONAL PRESERVATION
---------------------------
- No change to the database, migrations, RLS, capabilities, queries, RPCs,
  Server Actions, tenancy, credential or compliance logic, or auth.
- The invite flow is unchanged (InviteWorkerForm and its action). Worker
  record routes are unchanged and remain authoritative.
- Performance note: readiness is computed per current worker, and
  assignments per staffed shift in the 30-day window, using existing
  per-record loaders. A batched query would remove the fan-out, but it
  would be new backend work, so it is recommended for a backend stage.

13. INTENTIONAL PRODUCT / DATA DIFFERENCES
------------------------------------------
- Search, notification bell, and the Reports / Notifications / Settings /
  Staffing Requests / Credentials nav items do not exist in the product
  (as on Overview).
- No phone, email, location, availability (Available / Limited), photos,
  checkbox bulk select, role / availability / credential / facility / search
  filters, Message, Assign to Shift, or drawer Credentials / Assignments /
  Activity tab content.
- "Contact" → Reference; "Availability" → Today; "Up to date" → readiness
  labels.
- QA data: 8 real workers, so one page with no page buttons, against 142
  reference rows. Many cells are "—" because QA workers have no references
  or upcoming shifts.
- Logo descriptor: the canonical asset as supplied (see the S9A4 logo
  finding).
