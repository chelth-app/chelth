======================================================================
1. EXECUTIVE SUMMARY
======================================================================
Worker self-service now uses a dedicated P7 worker shell, WorkerShell. It
has:
  - a compact header (Shift Mark, agency, "Worker · name");
  - one centred content column;
  - a bottom navigation of real destinations: Shifts, Timesheets,
    Credentials, More;
  - a "More" sheet:
      - agency home;
      - Account;
      - Security;
      - Switch workspace (existing memberships, via
        selectOrganisationAction);
      - All workspaces (/app);
      - Sign out.

It is never the Agency sidebar or P1 shell, at any width.

Restyled in P7 card language:
  - My shifts (attendance cards, offers, assignments with Upcoming / Past
    tabs and a Shift details drawer);
  - clock in / out (a "Verify your location" panel with explicit
    privacy text, a location-check status, plain-language refusal titles
    and a success confirmation);
  - breaks;
  - the correction-request entry;
  - worker timesheets;
  - credentials.

No database, migration, RLS, capability, Server Action, RPC, rule or tenancy
behaviour changed.

3. WORKER MOBILE SHELL
======================================================================
Components:
  - src/components/layout/worker-shell.tsx (client): header, content
    column (max-w-xl, 576 px), fixed bottom nav, More sheet (native modal
    <dialog>).
  - src/app/app/organisations/[organisationId]/_components/
    worker-frame.tsx (server): loads the organisation, worker record,
    capabilities, profile and memberships, then renders WorkerShell. It
    falls back to the personal frame when there is no worker record (the
    page then applies its own 404, as before).

Where it applies:
  - (self-service) layout: My shifts, My credentials (+ detail), for
    everyone with a worker record;
  - (workspace) layout, self-service-only members (agency healthcare
    workers): Overview and their own Timesheets.
  - Staff who are also workers keep the workspace shell on staff pages and
    get the worker shell on their self-service pages.

The S1 layout separation is unchanged; only the frame chosen for
self-service changed.

7. SHIFT DETAIL
======================================================================
There is no worker shift-detail route, and no new route was created. Shift
detail is the modal DetailDrawer on each assignment ("Shift details: <facility>
<date>"). It shows:
  - date, time, timezone;
  - facility, location, discipline;
  - assignment state;
  - instructions;
  - attendance state (when present);
  - the next required action in words.

Only fields from the worker's own projection are shown: no agency notes, no
other workers, no pay.

8. CLOCK IN / CLOCK OUT
======================================================================
ClockControl logic is unchanged:
  - one-shot getCurrentPosition, only after the worker continues;
  - server time;
  - same server actions;
  - no faked success.

States now presented (from existing data and error codes):

  State                 What the worker sees
  --------------------  --------------------------------------------------
  Ready                 full-width "Clock in" (clock-out uses the outline
                        style)
  Explanation           "Verify your location" region (named "Location
  (before permission)   check"), with the reason and the privacy points;
                        "Share location and clock in" / "Not now"
  Requesting location   "Checking your location…" (role=status)
  Weak GPS              alert "Location not precise enough" plus the server
                        message (LOCATION_ACCURACY_TOO_LOW)
  Outside area          alert "Outside the site area" plus the server
                        message (OUTSIDE_GEOFENCE)
  Location unavailable  "Location not available" / "Location needed for
  or required           this site"
  Allowed with review   success "Clocked in. Recorded. Your agency will
                        review this attendance." (exception codes present)
  Success               "Clocked in." / "Clocked out." with "Recorded at
                        Chelth's server time."

Clock-out is offered whenever the server allows it (canClockOut). It is
hidden only during an active break, which is the existing rule, with an
explanation (§10).

======================================================================
9. LOCATION PRIVACY
======================================================================
The explanation appears before any location request and states:
  - the site checks you are on site when you clock in / out;
  - Chelth uses your location only for this attendance action and does not
    track you;
  - your location is read once, when you continue, and never in the
    background;
  - your agency sees the result, and precise location is kept as
    restricted evidence.

Coordinates are never shown to the worker. Sites without location checks
never prompt (E2E).

10. BREAKS
======================================================================
BreakControl is unchanged: "Start break" (outline), "End break" (primary),
server time, no location.

The card shows the "On break" chip and "You are on a break. End it before you
clock out." (role=status). Clock out returns once the break ends (E2E).

Event semantics are unchanged.

22. KNOWN VISUAL DIFFERENCES
======================================================================
1. No notification bell, avatar photo, facility photos, map, facility
   contact phone or parking notes (no product data). No "Home" tab; the
   agency home is in More.
2. Shift detail is a drawer, not a full page (no worker route exists).
3. No "Today" tab: the Attendance section is the "today" view (the
   existing projection around today), with Upcoming / Past for
   assignments.
4. The check-in step list ("Checking location ✓ / Within radius ✓") is a
   single status line plus a result panel; the server decides, so no
   client-side pre-checks are shown.
5. Clock-out is a neutral outline button, not red: danger colour is
   reserved for destructive actions.
6. No sticky bottom action bar: each card's single next action is inline,
   above the fixed navigation, to avoid duplicate controls.
7. The timesheet handoff has no editable break / notes fields: worker
   timesheets are derived from attendance and cannot be typed, which is
   the existing rule.
8. Requirements chips on shift details are not shown (readiness lives on
   My credentials).
