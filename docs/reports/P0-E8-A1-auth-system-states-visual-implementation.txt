8. LOADING STATES
-----------------
Audit: there are no route-level loading.tsx files. Form pending states
already exist: SubmitButton and Button have `loading`, a spinner and
aria-busy.

Deliberately not added: route-level loading boundaries. With streaming, a
loading.tsx makes Next.js send a 200 status before the page runs. A later
notFound() would then render the 404 UI with status 200, which would weaken
the secure, tenant-safe 404 behaviour asserted throughout the suite.

The LoadingState and StateIcon spinner now stop under
prefers-reduced-motion.


9. EMPTY STATES

The workspace chooser's empty case (/app) is now the canonical system

below.

11. ERROR / RETRY STATES
------------------------
SystemState (src/components/ui/system-state.tsx):
- locked card surface;
- luminous tile (coral for errors);
- page h1 (Manrope 24 / 700);
- one sentence;
- an optional support reference (digest);
- primary and optional secondary actions, stacked full width on phones.
- Exports: SYSTEM_CARD, stateActionClass (gradient primary) and
  stateSecondaryActionClass (outlined).

Boundaries:
- Only the safe ERROR_CODES.INTERNAL message and the digest are shown.
  Nothing implementation-related leaks (unit-tested).
- "Try again" (reset) is kept, and each recoverable boundary now has a
  safe fallback: "Back to your workspaces" (/app) inside the app, "Return
  home" outside.
- The global error uses the same state on the canvas wash.

Titles were made calm and consistent:
- "Something went wrong" → "This page could not be loaded" (in-app);
- "We couldn't load this page" (root / global).

ErrorState (src/components/ui/error-state.tsx), used inside auth cards:
- a compact coral notice (hairline, tint, error tile, h2, the safe
  message, optional reference and action);
- default title "This could not be completed".


12. SESSION / NETWORK STATES
----------------------------
- Session expiry: there is no client-side expiry UI. Protected routes

  restyled sign-in. No refresh behaviour was added.
- Network or service unavailable: no such state exists beyond the existing

20. KNOWN GAPS
--------------
- No dedicated canonical Auth reference exists, so this phase applies the
  locked system per DERIVATION-MAP §P9. A future approved Auth mockup may
  refine the composition.
- The sign-in failure uses the shared form alert (FormAlert) styling,
  which is also used by every form in the product. It was not restyled
  here to avoid a product-wide change.
- The personal frame (/app, /app/account, /app/security) keeps its
  existing header and background; only the verify panel and the empty
  chooser tile changed.
- Route-level loading states are intentionally absent (section 8).
- ERROR_CODES.INTERNAL keeps its existing wording ("Something went wrong
  on our side. Please try again.") because it lives in the shared error
  library used by every action. Changing it is out of scope for a visual
  phase.
