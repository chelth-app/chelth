2. SETTINGS ROUTE STRUCTURE
---------------------------
New route (approved): /app/organisations/[organisationId]/settings

settings/layout.tsx renders the page header and the secondary section nav.
Section pages:

  settings/              Organization            (all workspace members)
  settings/team          Team & Permissions      membership.view | membership.invite | role.assign
  settings/attendance    Attendance & Geofencing agency + attendance.manage_settings
  settings/payroll       Timesheets & Payroll    agency + (attendance.manage_settings
                                                 | payroll.approve + invoice.approve)
  settings/rates         Rates & Billing         agency + rates.view
  settings/compliance    Credentials & Compliance agency + credential.requirements.view
  settings/security      Security                (all workspace members)

- "Held" means granted or pending step-up, the same predicate as every page
  gate.
- A section that is not held is absent from the nav, and its URL returns
  404.
- Section switching is a URL change inside the same layout. The shell and
  header persist.

4. ORGANISATION SETTINGS
------------------------
Workspace Details (read-only):
- name, workspace type, status, workspace ID, your roles;
- the note: "The workspace name and type are set when the workspace is
  created and cannot be changed here".
- Chelth has no organisation rename, timezone, currency, contact or logo
  mutation, so there is no form and no Save/Cancel.

Operational Preferences (read-only summary, shown only for values the
caller can read):
- timesheet week start, payroll period, second approver, late clock-in
  threshold, raw location evidence retention, active baseline
  requirements;
- each has a "Change" link to the section that edits it, where the caller
  can.
Brand / Identity is not shown: no workspace logo feature exists.


5. MEMBERS & ROLES (Team & Permissions)
---------------------------------------
Moved from the Overview, with the same forms and gates:
- Members table: status chip, roles, Remove role, Assign role (role.assign;
  roles within the caller's ceiling), Suspend / Reinstate / Remove from
  organisation (membership.manage).
- Invitations: Create invitation, Resend, Revoke (membership.invite).
- Role Permissions: read-only list of the organisation type's roles and
  their permission counts. Roles are defined by Chelth and are not
  editable here.
The database still enforces the role ceiling, the last-admin rule and
step-up.


6. SECURITY
-----------
Your Account Security (an account setting, not organisation-wide):
- whether an authenticator app is set up (listMfaFactors);
- this session's assurance ("Verified with authenticator" / "Password
  only");
- links to the existing personal Security page (/app/security, returning
  here) and to Account.
- The fixed rule is stated: administration and privileged actions require
  authenticator verification.

Audit Log (audit.view): the organisation's append-only audit events (moved
from the Overview's "Recent activity").

Not shown, because they don't exist: MFA-policy, session-timeout and
session-revocation settings.


7. ATTENDANCE & LOCATION
------------------------
- Check-In Rules: the existing AttendanceSettingsForm (7 thresholds) with
  the same server validation. Saving was verified in E2E ("Attendance rules
  saved.").
- Location Evidence Retention: the existing RetentionForm (bounded
  7–365 days).
- Geofence Defaults: Chelth has no workspace-wide geofence default.
  Geofences (position, radius, accuracy, outside-area policy) are set per
  facility location, so this card links to Facilities.
- The moved panel is replaced on the Attendance page by a link to
  Settings.


8. COMPLIANCE SETTINGS
----------------------
Credentials & Compliance follows "settings configure, compliance
monitors":
- a read-only summary of the active baseline requirements (verification,
  minimum validity, warning window), from listRequirements;
- links to manage the baseline on Compliance and facility requirements on
  Facilities.
The requirement forms are not duplicated in Settings.


9. NOTIFICATION PREFERENCE DECISION
-----------------------------------
Omitted. Chelth has no notification preference model: every current
outbox event is a required operational email (NOTIFICATION_CATEGORY), and
there is no in-app inbox. No unread, badge, archive or delivery
preferences are exposed. In-app Notifications stays in
docs/architecture/POST_VISUAL_PRODUCT_BACKLOG.md. No sidebar Notifications
item and no bell.


10. FINANCE CONTROLS
--------------------
Timesheets & Payroll covers:
- Timesheet Week: the existing WeekStartForm (attendance.manage_settings).
- Pay Period and References: the existing FinancialSettingsForm (period
  type, anchor date, payroll / invoice prefixes).
- Finance Controls: the existing MakerCheckerForm (second approver, the
  financial_maker_checker setting).
- The financial forms need payroll.approve + invoice.approve, as on the
  Payroll page; the RPCs enforce the same.
- Copy: "Chelth prepares and exports financial documents; it never
  executes payments."
- No payment, tax, bank or payout settings.

Rates & Billing:
- Rate Integrity Rules: rate cards and rounding/overtime policies are
  versioned; this card links to Rates.
- Invoice Numbering: the current prefixes, read-only, with a link to edit
  them where allowed.
- No currency, invoice terms or billing contact settings exist.

The moved Payroll-page panel is replaced by a link to Settings.


11. ACCOUNT VS ORGANISATION SEPARATION
--------------------------------------
- Organisation settings: tenant administration (team, policies, controls,
  audit).
- Account: the personal /app/account and /app/security routes
  (authenticator enrolment and verification), linked from Settings →
  Security and from the workspace switcher. They are not merged.


12. AAL2
--------
Unchanged:
- Privileged capabilities pending step-up keep sections listed but show
  the canonical StepUpNotice ("Verify now"), returning to the same section.
- Mutating forms render only when the capability is granted.
- Verified in E2E:
  - Team shows Members but no Create invitation before step-up;
  - after TOTP verification it returns to settings/team with Create
    invitation.


13. CAPABILITY FILTERING
------------------------
- Sections are capability-driven (section 2), never role-name-driven.
- E2E: agency admin sees 7 sections. The scheduler sees Organization,
  Security and the sections their capabilities allow; payroll and rates
  return 404.
- A facility admin sees no agency-only sections and gets 404 on the
  agency's Settings.


14. WORKSPACE SCOPING
---------------------
- Every read and action is scoped to the route's organisation id through
  loadOrganisationPage and RLS.
- The workspace switcher behaviour is unchanged. Settings never mixes
  memberships; the "Your roles" value is from the caller's membership in
  this organisation only.
