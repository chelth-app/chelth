1. ROOT ROUTING CHANGES
-----------------------
File: src/app/page.tsx

`/` is now a server redirect, using the existing identity helper (the same
getAuthIdentity the sign-in page uses):
- signed out → /sign-in;
- signed in → /app, the existing app entry and workspace chooser.

/app keeps its existing behaviour: it lists memberships and does not
auto-open a workspace.

Unaffected, because they never pass through `/`:
- invite links (/invite);
- recovery links (/auth/confirm → /reset-password);
- the safe `next` handling, which stays exactly as it is on /sign-in.

Sign-out still redirects to `/` (unchanged action); a signed-out visitor
then lands on Sign in.

No auth primitive, proxy, middleware or redirect validator was changed.


2. PLACEHOLDER RETIREMENT
-------------------------
The coming-soon page has been removed from the app domain:
- "Reliable workforce operations for healthcare staffing.";
- "The Chelth platform is being established… upcoming releases.";
- its Sign in / Create account buttons.

The root no longer advertises "Create account". /sign-up is untouched, and
the sign-in page keeps its existing "New to CHELTH? Create an account"
link, which is part of the current product model: identities sign up, then
join by invitation or create an agency. See section 15.

5. WORKSPACE-CARD TREATMENT
---------------------------
Each card is an article named after the organisation, with:
- the locked card surface (14 px radius, teal hairline, white → cool-mint,
  two-layer shadow);
- a luminous identity tile (workforce icon for agencies, facility icon for
  facilities);
- the organisation name (Manrope 18 / 600);
- chips:
  - type (Agency / Facility; informational tone);
  - "Suspended" when the organisation is suspended (warning);
  - "Last used", only when it matches the real stored preference
    (neutral, restrained);
- a role line (section 6);
- "Open workspace": full-width locked primary, posting the existing
  selectOrganisationAction. The accessible name is "Open workspace
  <organisation>", which is unique per card.


6. ROLE-LABEL TREATMENT
-----------------------

(queried once per organisation type present):

"1 role(s)" no longer appears (asserted). A screen-reader prefix reads
"Your role:".

15. KNOWN GAPS
--------------
- Public sign-up: the sign-in page still links to /sign-up ("New to
  CHELTH? Create an account"). Sign-up plus "Create a new agency" is the
  current product model, and the brief forbids changing signup policy.
  Hiding the link would be a product decision; it is flagged here, not
  made.
- The header does not show the signed-in identity: the frame does not load
  the profile, and adding that read to every personal / fallback page was
  out of scope. The chooser greets the user by name.
- Account and Security page bodies keep their existing card styling
  inside the new frame (no functionality change was requested).
- "Last used" depends on the existing preference cookie. It is shown only
  when it matches a membership.
