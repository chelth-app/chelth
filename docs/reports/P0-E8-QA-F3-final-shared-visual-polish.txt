------------------------------

the select / input inside measured 42 px.

control is 44 px. Desktop is unchanged, because it was already
`sm:h-[46px]`. The changed wrappers:

- LockedFilterSelect (finance-locked: Rates, Pricing, Payroll, Invoices,
  facility Staffing requests, facility Sign-off);

  Compliance and Facilities;
- the Shifts toolbar.

Inputs inside these wrappers:
- The text and date inputs (search on Timesheets, Workforce, Compliance
  and Facilities; the period / date inputs on Timesheets, Shifts and the
  Attendance window) were only about 24 px tall. Taps on the wrapper
  padding missed them.
- They now carry `h-full`, so the whole 44 px area is the target. They are
  visually identical (transparent inputs).

The Attendance window control (date range) is 46 px on phones and keeps
its 44 px desktop height.

Query and filter logic are untouched. The legacy FilterBar (worker record
only; not a locked filter row) is unchanged.

6. TABLE OVERFLOW RESULTS
-------------------------
Method:
- A temporary, env-gated hook in the e2e capture helper measured every
  overflow-x region at 1280 and 1512 on every page the desktop suite
  captures. That covered the Finance, Timesheets, Workforce, Facilities,
  Overview, Attendance, records and worker pages with real data.
- The hook was removed afterwards; support.ts keeps only the two
  QA-capture lines in section 15.

Before → after at 1280 (px of horizontal overflow):

  Workers table             25 → 0  min-w 1040 → 1008 (table-fixed;
                                    columns about 3% narrower)
  Client facilities table   25 → 0  min-w 1040 → 1008 (same)
  Staffing requests (Over-  20 → 0  min-w 40rem → 38.5rem. This only
  view panel)                       applies below the panel's previous
                                    minimum.
  Priced lines              67 → 0  min-w 1040 → 960. The money columns
                                    keep their natural width.
  Agency timesheets,         0      already 0 in the current tree. The
  Rate cards, Payroll               QA1 values of 6–7 px were not
  batches, Invoice drafts,          reproduced, so no change was needed.
  facility Staffing
  requests

Left scrollable, by design:
- Scheduled workers table (Attendance): 203 px at 1280, 54 px at 1512.
  The table genuinely needs about 820 px inside a 620–770 px region (it
  shares the row with the attendance side column). The scrolling is real
  and needed, so the scrollbar stays.
- Timesheet entries: 320 px. Measured on the WORKER timesheet record,
  where the entries table sits in the ≤576 px worker column. Its
  per-shift columns (scheduled, worked from–to, breaks, worked,
  sign-off) need the width, so scrolling inside the labelled region is
  correct. The agency timesheet record has no overflow at 1280 / 1512.
- Today's schedule table (Overview): 9 px. The table's min-width (36rem)
  already fits; the overflow is intrinsic cell content on the canonical
  Overview (B). It was not touched, to avoid disturbing the locked
  Overview; this is a candidate for the verification audit.

At 1024 / 768, scrolling inside labelled regions remains (intended). No
scrollbar was hidden anywhere, and no page-level overflow exists at any
width (suite assertion).
