4. SUMMARY / KPI AREA
---------------------
Real counts in the four reference slots. Each is a working shortcut:
- Active Facilities: facilities with status active. Links to ?status=active.
- Open Requests: upcoming facility-sourced shifts that are requested, or
  open and not filled. Links to ?requests=1.
- Shifts This Week: upcoming shifts starting within 7 days. Links to Shifts
  from today.
- Needs Attention: active facilities whose relationship is not active, or
  that have no active location. Links to ?attention=1.

Shift cards need SHIFT_VIEW; relationship logic needs RELATIONSHIP_VIEW.


5. FILTERS
----------
Real display filters over the loaded list, as native GET (same mechanism as
the existing status filter):
- Status (facility status);
- Facility type (only types present);
- Relationship (pending / active / suspended / ended, with
  RELATIONSHIP_VIEW);
- Search (name or locality);
- Apply, and Clear when any filter is active.

Not offered, because no data exists: region and unit filters.
Pagination is 10 per page and keeps every filter.


6. FACILITIES TABLE / DIRECTORY
-------------------------------
A frosted card with a 47 px header band and 62 px rows. Columns:
- Facility: tile, name, type.
- Location: locality and location count.
- Contact: the facility phone and email, from the record, when present.
- Open Requests: count pill, coral when above zero.
- Upcoming Shifts: blue count pill.
- Roles Used: discipline codes on upcoming shifts.
- Status: facility status, or "Needs attention".
- Relationship: lifecycle chip.
- ⋮: Facility Details.

"Last Activity" became Relationship: there is no activity data.
There is no checkbox column: no bulk actions exist.


7. FACILITY IDENTITY
--------------------
- No facility photos: an 84 px luminous mint tile with the duotone
  facilities icon.
- Name, type, and locality (or timezone) with a pin.
- No invented addresses: the address shows only from the record's address
  fields.


8. FACILITY DRAWER
------------------
The canonical drawer, unchanged, with Facilities content:
- Title "Facility Details"; identity block; status chip.
- Rows: Relationship (lifecycle chip), phone and email when present, and
  "Linked to / Not linked to a CHELTH facility organisation".
- Tabs, all real:
  - Overview:
    - Facility Information: type, address when present, locations, roles
      on upcoming shifts;
    - three stat tiles: Open Requests, Upcoming Shifts, Locations;
    - Recent Requests (2) with "View all".
  - Requests: facility requests.
  - Shifts: upcoming shifts.
  - Locations: name, timezone, active / inactive.
  - Request and shift rows link to the shift record.
- Actions:
  - primary "View Shifts": Shifts filtered to this facility
    (?facilityId=…), an existing filter;
  - secondaries "Facility Record" and "Relationship" (record
    #relationship-heading, with RELATIONSHIP_VIEW).

Not offered:
- "Create Request": agency-side request creation pre-scoped to a facility
  does not exist. Requests are submitted by facility users, and agency
  shift creation has no facility pre-selection.
- "Message Facility": there is no messaging.
- Activity tab: there is no activity data.
