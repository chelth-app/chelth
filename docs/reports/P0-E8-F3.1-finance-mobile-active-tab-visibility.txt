P0-E8-F3.1 — FINANCE MOBILE ACTIVE-TAB VISIBILITY FIX
=====================================================

Branch: p0-e8-visual-implementation (uncommitted)
Scope:  Finance shell only (FinanceWorkspaceNav). No routes, page
        content, permissions, finance logic, sidebar or desktop spacing
        changed. No screenshots were saved to the repository.


1. ROOT CAUSE
-------------
The Finance tab row (SectionTabs <nav aria-label="Finance">) is a
horizontal scroll container (overflow-x: auto). It always starts at
scrollLeft 0.

At 375 and 412 px, the "FINANCE" label plus four tabs are wider than the
row. The tabs to the right, Invoices most of all (the last tab), started
partly or fully outside the visible part of the row, and nothing brought
the current tab into view.


2. IMPLEMENTATION
-----------------
File: (finance)/_components/finance-workspace-nav.tsx

- A ref on the shell, and a useEffect keyed on the pathname. The layout
  keeps the shell mounted across finance routes, so the effect runs on the
  first render and after every client-side navigation.
- The effect finds the Finance row (nav[aria-label="Finance"]) and its
  current link ([aria-current="page"]). It returns at once when there is no
  overflow (scrollWidth ≤ clientWidth), which covers every desktop width.
- If the current tab extends past the right edge of the row, the row
  scrolls right by exactly that overflow. If it starts before the left
  edge, the row scrolls left by exactly that amount. Otherwise, nothing
  happens.
- Only row.scrollLeft is set. This is equivalent to scrollIntoView with
  inline "nearest", but it can never scroll the page:
  - no vertical or page movement;
  - no smooth scrolling, so the adjustment is instant on the first render;
  - no focus change;
  - no live-region announcement.
- Tab order, labels, styles, spacing and focus treatment are unchanged.
