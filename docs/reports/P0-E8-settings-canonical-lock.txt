1. SCOPE
--------
This pass locks the approved Settings visual language as shared code and
documentation. It does not redesign anything.

items in section 4, the only visible changes are:
- the related-area cards now have equal height (section 5);
- other Settings sections now use the canonical action button for
  standalone links (section 2).

Unchanged: Supabase, auth, RLS, migrations, RPCs, routes, capability checks,
business logic, financial controls, attendance behaviour, credential logic
and the data model. No data loader, gate or mutation was touched.

3. REUSABLE SETTINGS PATTERNS LOCKED
------------------------------------
Mapping to the requested component names:

- SettingsLayout → settings/layout.tsx (existing; unchanged)
- SettingsSubnav / SettingsSubnavItem → SettingsNav (existing; refined,
  section 4)
- SettingsCard → the locked Panel inside .chelth-locked. It is not wrapped:
  an alias would add no value, and Panel is already the single card.
- SettingsIconTile (new)
  - 36 px, 10 px radius, 18 px icon at 2.1 stroke.
  - Mint by default.
  - info / warning / danger tints use the locked KPI tile values. Use them
    only when the row means that status.
- SettingsExplanationList / SettingsExplanationRow (new)
  - The record-list hairlines and 56 px rows.
  - Title 15 / 600 heading ink, one 13 px slate line, optional trailing
    chips.
  - Used for both the readiness inputs and the requirement rule rows.
- SettingsStatusSummary (new)
  - A "Results:" label (13.5 / 500 slate), then compact RefChips (400).
- SettingsActionRow / SettingsActionLink (new)
  - The outlined secondary CTA: 44 px, 8 px radius, rgba(0,90,96,0.35)
    border, 14 / 600 navy.
  - Optional 18 px teal-dark icon; 10 px gap.
- SettingsRelatedLinks (new)
  - Navigation-only link cards: tile, 14.5 / 600 title, 12.5 slate
    purpose.
  - 1 / 2 / 3 columns.

The explanatory pattern ("How Readiness Is Calculated") and the rule-card
pattern ("Credential Requirement Rules") are written down as locked
structures in the visual-system doc, with the rule that no editable control
appears without a backing mutation.

Semantic chips (unchanged values; now documented):
- Ready / Active / Requirement met = success;
- Warning / Action required = warning (amber);
- Error / Not eligible = danger (red);
- informational = info (blue) or neutral (slate).


4. INTERNAL NAV TREATMENT
-------------------------
Unchanged: radius 8 px; height 46 px (44 px touch); 21 px icon at 1.9
stroke in a 22 px column; 14.5 px label at 500, current item 600 heading
ink; mint-mist 80% fill; 3 px teal left rule.

Added:
- A restrained navy hairline on the selected item, rgba(12,30,70,0.09),
  as the lock specifies. It has no shadow.
  - Non-selected items carry a transparent 1 px border, so nothing shifts.
  - The primary sidebar's selected pill (dark teal gradient with lift)
    stays clearly dominant: primary sidebar > internal Settings nav.

Fixed (found during screenshot QA; both existing issues):
a) Desktop sticky offset
   - Problem: the subnav stuck at top: 16 px, under the 76 px sticky top
     bar. Once the page scrolled, the top bar covered "Organization".
   - Fix: it now sticks at 92 px (16 px below the top bar).
b) Phones and tablets
   - Problem: below lg the subnav is one horizontally scrolling row. It
     always opened at the start, so on deeper sections the selected item
     was off-screen (at 412 px, Credentials & Compliance was not visible).
   - Fix: on load and on navigation, the nav now scrolls its own row to
     the current item. The page's scroll position is never changed.
   - No selector, menu or second mobile pattern was introduced.
