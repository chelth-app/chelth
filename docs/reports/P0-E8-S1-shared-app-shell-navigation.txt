1. EXECUTIVE SUMMARY
======================================================================
The authenticated Agency / Facility routes under /app/organisations/[id]/**
now render inside one shared workspace shell (approved parent P1):
  - dark-teal sidebar with the canonical reverse logo;
  - capability-driven navigation;
  - top bar with the workspace context and a user/workspace control
    (Account, Security, Switch workspace, Sign out);
  - an off-white canvas with a wider content container.
Below the lg breakpoint the same sidebar opens as an accessible modal
overlay from a menu trigger (G1). There is no bottom navigation, no search
field and no notification bell (F10).

Workers are not moved into the shell. Self-service pages and self-service-
only members keep the existing personal frame.

Changed:
  - layouts and route groups (URLs unchanged);
  - shell components;
  - shell tokens;
  - one pure navigation builder;
  - docs and tests.

Unchanged:
  - page bodies, forms and tables;
  - Server Actions, RPCs and capabilities;
  - memberships and RLS;
  - migrations, and AAL2 / step-up behaviour.

No backend or database change was needed.

4. NEW APPSHELL ARCHITECTURE
======================================================================
The frames are separated by route groups. Folders were moved with git mv;
no URL changed and the typed routes are identical, as the build route list
confirms.

  src/app/app/layout.tsx
      Authentication redirect only (UX). No visual frame.
  src/app/app/(personal)/layout.tsx
      PersonalFrame for /app, /app/account and /app/security[/verify].
  src/app/app/organisations/[organisationId]/(workspace)/layout.tsx
      Server layout. It loads:
        - the identity and profile;
        - the organisation (RLS);
        - my_capabilities;
        - my memberships;
        - the role names;
        - my worker record (agency only).
      It renders AppShell for workspace staff. Otherwise it renders
      PersonalFrame, which covers self-service-only members and invalid or
      invisible ids (the page then returns 404 exactly as before).
      Hosts:
        - Overview (hub);
        - operations, shifts, attendance and timesheets;
        - workforce, facilities and compliance;
        - rates, pricing, payroll and invoices;
        - staffing-requests;
        - all detail pages.
  src/app/app/organisations/[organisationId]/(self-service)/layout.tsx
      PersonalFrame for my-shifts and my-credentials, unchanged.
  src/app/app/_components/personal-frame.tsx
      The previous header and frame, moved verbatim.
  src/app/app/exports/... (route handler)
      Untouched.

Components (src/components/layout; no second component system):

  AppShell (client)
      lg+ grid: 15rem sidebar + content column. Owns the overlay state.
  WorkspaceSidebar (client)
      Reverse logo, then <nav aria-label="Workspace"> with grouped lists.
  SidebarNavItem
      A Next Link. aria-current="page" uses an exact match for Overview
      and a prefix match for sections.
  WorkspaceHeader
      Contains, in order:
        - the menu trigger (below lg);
        - the Shift Mark (below lg);
        - the workspace name and type;
        - the WorkspaceSwitcher.
  WorkspaceSwitcher (client)
      The user/workspace disclosure (G2).
  MobileWorkspaceNav (client)
      The sidebar inside a native modal <dialog>.
  workspace-nav-icon.tsx
      Inline SVG line icons. No icon dependency; CSP-safe.
  workspace-navigation-model.ts
      Nav types and isNavItemActive (pure).
  PageContainer
      New size="wide" (max-w-screen-2xl) used by the shell. Default stays
      max-w-6xl.

The shell receives Server Actions (selectOrganisationAction,
signOutAction) as props from the server layout. Client code therefore
never imports a feature index that contains server-only modules. To allow
this, signOutAction is now also exported from @/features/identity.

7. CAPABILITY VISIBILITY
======================================================================
buildWorkspaceNavigation (src/features/organisations/workspace-navigation.ts)
is a pure function of:
  - the organisation type;
  - can(capability), from my_capabilities;
  - hasWorkerRecord.
It never looks at role keys.

An item is listed when the capability is "held" (granted or pending
step-up). This is the same predicate as requireCapabilityOrNotFound and as
the hub's section links, so the navigation can never offer a page that
returns 404, and it never hides a page the user can open.

The navigation is a UI hint only. Every page keeps its own server gate,
and every RPC is still authorised by the database.

Audience:
  - isWorkspaceStaff(grants) is true when the caller holds any grant
    besides organisation.view.
  - Agency healthcare workers (organisation.view only) are self-service
    users and keep the personal frame.

E2E (scheduler) visits every listed href and asserts HTTP 200. It also
asserts that an unlisted one (payroll) returns 404.

8. WORKSPACE SWITCHING
======================================================================
WorkspaceSwitcher is a disclosure: a button with aria-expanded and
aria-controls, and a panel of ordinary links and buttons in tab order. It
is not an ARIA menu.

Trigger: initials avatar, user name and role (the name is visually hidden
below sm but stays in the accessible name "Account and workspace menu: …").

Panel:
  - name and email;
  - "Current workspace": name, type, role, and Suspended if applicable;
  - "Switch workspace": the caller's other existing memberships (from
    listMyMemberships), each a form posting to the existing
    selectOrganisationAction. That action re-checks visibility, writes the
    UI-preference cookie and redirects. The section also links to "All
    workspaces" (/app, the full chooser);
  - Account, Security, Sign out (the existing signOutAction).

Single-workspace users see no switch section (no switcher complexity).
No membership behaviour was created or changed.

Closing:
  - Escape closes the panel and returns focus to the trigger;
  - an outside pointer press or focus leaving the control closes it.

======================================================================
lg (1024px) and up:

  - The content uses PageContainer wide (max 1536px) on the Off White

  - Detail pages keep their section active through a prefix match that is

======================================================================
10. TABLET/MOBILE BEHAVIOUR
======================================================================
Below lg (phones and tablets, including landscape tablets under 1024px):
  - The persistent sidebar is display:none (not in the page or the
    accessibility tree).
  - The top bar shows the menu trigger. It has the accessible name "Open
    navigation", aria-haspopup="dialog", aria-expanded and aria-controls.
  - The overlay is a native modal <dialog> named "Workspace navigation".
    showModal() provides:
      - a focus trap;
      - an inert (blocked) background, verified with :modal in E2E;
      - Escape to close;
      - focus return to the trigger.
  - Initial focus is on "Close navigation".
  - The overlay also closes on a backdrop click, on choosing a
    destination, and on any route change.
  - No bottom navigation (G1).
  - No horizontal overflow caused by the shell: E2E asserts
    scrollWidth <= clientWidth at Pixel 7 width.
  - The workspace name truncates. The switcher panel is capped at
    calc(100vw - 2rem).

11. WORKER ROUTE SEPARATION
======================================================================
The separation is by route group and audience, with no pathname sniffing:
  (a) my-shifts and my-credentials live in the (self-service) group, whose

      still linked from Overview's section links, as before.

17. KNOWN VISUAL DIFFERENCES (vs P1)
======================================================================
 1. No global search field and no notification bell in the top bar. This
    is the locked decision F10: neither feature exists.
 2. No Notifications or Settings entries below the divider, and no Reports,
    Credentials register or agency Staffing Requests (F6: no routes). The
    lower sidebar is therefore emptier than the reference.
 3. No mint wave artwork at the sidebar foot: no approved asset exists in
    public/brand, and it is not to be improvised.
 4. The sidebar tint is a restrained vertical Teal Dark → (Teal Dark+Navy)
    token blend, not the prototype's colours.
 5. The active pill is Deep Teal with a Mint indicator bar. The reference
    pill has no indicator bar; it was added so the state is not
    colour-only.
 6. Sidebar groups carry small uppercase headings ("People and
    compliance", "Finance"). The reference has a flat list. This was added
    for scanability with up to 12 items.
 7. The top bar shows the workspace name and type on the left, where the
    reference has search. The P1 top bar has no workspace context; G2
    requires it.
 8. The avatar shows initials (there are no profile photos).
 9. Page content is NOT restyled (S1 scope). Page titles are still
    text-2xl rather than the reference's 32px Manrope. The hub keeps its
    "All organisations" link, its role badges and its section link
    buttons, which now duplicate the sidebar. Removing them is S2/S3 work.
10. Sidebar width is 240px (the reference is about 210–225px), so the
    48px-minimum reverse lockup fits with padding.
11. Narrow-viewport behaviour has no reference (G1). The overlay design is
    derived from the desktop sidebar.
