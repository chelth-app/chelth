E. CREATE SHIFT DECISION
------------------------
Implemented as a presentation-only disclosure. Nothing about creation
changed.

How it works:
- The existing create-a-shift section (same CreateShiftForm, Server Action,
  validation, fields and route) is hidden by default when the user can
  schedule (at least one location).
- It is revealed by the "+ Create shift" link (href="#create-shift") through
  the CSS :target selector. No script, no new workflow and no modal.
- Because the hash persists, a validation error after submit still shows
  the form. A "Close" link (to #shift-list-heading) hides it again.
- When no schedulable location exists, the existing guidance message is
  still shown, unhidden, so the capability gap stays explained.

Why this is not a material behaviour change:
- The creation flow is identical once revealed.
- The two E2E flows that create shifts through the UI
  (shifts-assignments, assignment-operations) now click "+ Create shift"
  first. They assert the form is hidden before and visible after, then run
  the unchanged creation assertions.
- No assertion was weakened.

Result: the list composition now matches the PNG. The primary "+ Create
shift" sits at the end of the filter row, and no form sits under the table.
