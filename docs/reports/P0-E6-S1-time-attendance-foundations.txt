CHELTH — P0-E6-S1 TIME & ATTENDANCE FOUNDATIONS
Stage report · 2026-09-30 · branch p0-e6-s1-time-attendance (uncommitted)

======================================================================
1. EXECUTIVE SUMMARY
======================================================================
Chelth now records when an accepted worker actually started and finished a
shift. The record is operationally trustworthy, and it is not surveillance.

  - Server-authoritative time. Every device clock event takes the
    database clock (now()). The client never sends an event time, and a
    check constraint enforces occurred_at = recorded_at.
  - Append-only history. Events and location evidence can never be
    updated, deleted or truncated. The attendance summary is a projection
    rebuilt from events by a single writer.
  - Clock-in eligibility is tied to the accepted assignment. Clock-in
    re-runs the canonical eligibility gate (compliance, activity) and
    applies configurable timing rules.
  - Clock-out is never blocked by location, assignment status or
    relationship state: a worker can always record leaving.
  - Optional geofence per facility location, validated in the database
    (haversine). Policies: block, or allow and flag for review. There is
    exactly one location reading per explicit clock action, with an
    explanation shown BEFORE the browser prompt. There is no tracking.
  - Raw coordinates live in one restricted, append-only table:
      * readable only with attendance.location.view (AAL2);
      * every read is audited;
      * never in audit metadata, notifications, facility views or worker
        history.
  - Exceptions:
      * late and early clock events;
      * missed clocks, detected by an idempotent 15-minute scan;
      * outside the site area, imprecise or unavailable location;
      * not eligible at clock-in;
      * correction requested.
    Each exception notifies attendance.review holders once.
  - Corrections. A worker requests a correction; a reviewer approves or
    rejects it. Approval appends a corrected_* event and the original event
    stays. Nobody can review their own attendance.
  - Surfaces:
      * agency /attendance page;
      * attendance on the agency shift detail;
      * a narrow facility view ("Attendance for this request": no
        coordinates, no exception detail);
      * mobile-first clock in/out on /my-shifts.
  - Validation: all 13 checks pass.
      * pgTAP: 865 assertions in 20 files, including all 25 required cases
        (A–Y);
      * integration: 76 tests;
      * unit: 190 tests;
      * E2E: 82 passed, 2 skipped. The skips are existing desktop-only
        keyboard tests.
  - Security: no open HIGH or CRITICAL finding.

Not built, as instructed: payroll, invoicing, rates, overtime, exports,
billing, timesheet approval, continuous or background GPS, route tracking,
live maps, biometrics, facial recognition.

2. ATTENDANCE SCHEMA
======================================================================
Migration 20260930140100_attendance_tables.sql:

  agency_attendance_settings
    One row per agency, with timing rules in bounded integer columns. No
    row means the documented defaults apply. Readable with attendance.view.
  location_geofences
    One row per facility location:

    identity and the full shift and location identity.
  attendance_events

  attendance_exceptions
    Type, severity, detected_by, status and resolution. At most one open
    row per (attendance, type). Never deleted.
  attendance_corrections
    Requested type, time, reason, optional note (≤ 500 characters) and
    review fields. At most one pending row per (attendance, type). Never
    deleted.

======================================================================
3. EVENT MODEL
======================================================================
Event types: clock_in, clock_out, corrected_clock_in, corrected_clock_out.

Fields:
  - occurred_at: when the event happened;
  - recorded_at: database time of the write;
  - source: worker_device or approved_correction;
  - geofence_result: a result code, never coordinates;
  - actor_profile_id;
  - correction_id: required exactly when the source is
    approved_correction;
  - segment: always 1 for now; reserved for split shifts.

Constraints:
  - device events must have occurred_at = recorded_at;
  - approved_correction ⇔ corrected_* ⇔ correction_id is present;
  - unique indexes allow one clock_in and one clock_out per segment;
  - UPDATE, DELETE and TRUNCATE are refused by triggers for every role,
    including the owner.

Effective time is the latest corrected_* event, otherwise the device
event. See docs/architecture/ATTENDANCE_EVENT_MODEL.md.

======================================================================
4. ATTENDANCE STATE MODEL
======================================================================
Stored states: not_started → clocked_in → clocked_out. Corrected events
can also establish either time.

Displayed state adds "Needs review" whenever open exceptions exist
(deriveAttendanceState). Labels: Not started, Clocked in, Completed,
Needs review.

internal.refresh_attendance is the only writer of the projection. It runs
after every command, review and scan change.

======================================================================
5. CLOCK-IN ELIGIBILITY
======================================================================
Checks run in this order:

  1. Own assignment. Uses a live membership (is_own_active_worker).
     Locks: relationship FOR SHARE, then assignment FOR UPDATE.
  2. Shift state:
       - shift cancelled: CHT06;
       - shift not open: CHS09;
       - assignment not accepted: CHT05.
  3. Relationship is active: CHS10.
  4. Timing window: CHT07 before the window, CHT08 at or after the end.
  5. Clock state: CHT09 if already clocked in, CHT11 if already clocked
     out.
  6. Geofence with a blocking policy:
       - no location: CHT12;
       - accuracy too low: CHT14.
  7. Canonical eligibility gate (internal.assignment_eligibility), then a
     blocking geofence with an outside result. A refusal here COMMITS:
       - outcome 'refused' with WORKER_NOT_ELIGIBLE, WORKER_NOT_ACTIVE or
         OUTSIDE_GEOFENCE;
       - an urgent exception;
       - one agency notification;
       - an audit event.
     The server action maps the refusal to a safe AppError.

======================================================================
6. TIMING RULES
======================================================================
Rules are set per agency with set_agency_attendance_settings. This needs
attendance.manage_settings (AAL2) and is audited.

  Rule                       Default   Bounds
  early clock-in window        30 min    0–240
  late clock-in threshold       5 min    0–120
  early clock-out threshold    15 min    0–240
  late clock-out threshold     30 min    0–240
  missed clock-in grace        15 min    5–240
  missed clock-out grace       60 min    15–720
  clock-out cut-off           240 min    60–1440
                                         (must be ≥ missed clock-out grace)

  - All comparisons use now() against the shift's UTC start_at and end_at.
  - Display always uses the shift's own timezone.
  - The UI shows the configured values in a "Timing rules" form.

======================================================================
7. CLOCK-OUT
======================================================================
Requires clocked_in: CHT10 if not clocked in, CHT11 if already clocked
out.

  - After end + cut-off: CHT18, and the worker requests a correction
    instead.
  - Never blocked by location, assignment status or relationship state.
  - Location problems and early or late timing become exceptions.
  - Resolves missed_clock_out.

======================================================================
8. GEOFENCE MODEL
======================================================================
  - Optional, per facility location. Configured on the agency facility
    page with set_location_geofence (attendance.manage_settings, AAL2).
  - Composite FKs bind a geofence to (location, facility, agency).
  - Policies:
      * block: outside refuses clock-in;
      * allow_with_review: record the event plus an exception.
  - See docs/architecture/GEOFENCE_MODEL.md.

======================================================================
9. LOCATION PRIVACY
======================================================================
  - One getCurrentPosition call per clock action. No watchPosition, no
    polling, no background location, no maps.
  - The explanation region ("… uses your location only for this attendance
    action and does not track you") is shown before the browser prompt,
    with "Share location and clock in" and "Not now".
  - Coordinates are stored only when the location's geofence is enabled.
  - Raw coordinates are available only through
    list_attendance_location_evidence (attendance.location.view, AAL2), and
    each read is audited.
  - Everyone else sees result labels only.
  - Coordinates never appear in audit metadata (tested), emails, or the
    facility or worker projections.
  - See docs/security/ATTENDANCE_LOCATION_PRIVACY.md.

======================================================================
10. GEOFENCE VALIDATION
======================================================================
internal.check_geofence does all validation server-side:

  1. no enabled geofence: not_required, and the input is ignored;
  2. invalid input: CH400. This covers a missing half of a coordinate
     pair, out-of-range values, and accuracy below 0 or above 100 km;
  3. no coordinates: unavailable;
  4. haversine distance with R = 6 371 008.8 m;
  5. accuracy missing or above the maximum: low_accuracy;
  6. distance ≤ radius: inside; otherwise outside.

The client never declares a result. The evidence row stores the distance
and radius used.

Tested edges:
  - 199.5 m is inside and 200.5 m is outside a 200 m fence;
  - a 1000 m meridian distance is exact to 1 cm;
  - accuracy worse than configured is low_accuracy even at the site;
  - geofences are location-scoped.

======================================================================
11. ATTENDANCE EXCEPTIONS
======================================================================
Types (10):
  - late_clock_in, early_clock_out, late_clock_out;
  - missed_clock_in, missed_clock_out;
  - outside_geofence, poor_location_accuracy, location_unavailable;
  - assignment_not_ready;
  - manual_correction_requested.

Statuses: open → under_review → resolved | dismissed. Resolved and
dismissed are terminal, enforced by a trigger.

Resolutions:
  - system: clocked_in, clocked_out, correction_approved,
    correction_rejected, assignment_closed;
  - reviewer: acknowledged, not_applicable.

Rules:
  - At most one open row per type, so detection and notification are
    idempotent.
  - Exceptions cannot be deleted.
  - review_attendance_exception needs attendance.review and refuses the
    reviewer's own attendance (CH403).

======================================================================
12. MISSED CLOCK DETECTION
======================================================================
internal.run_attendance_scan() runs as pg_cron job chelth-attendance-scan
every 15 minutes. Each run is recorded in internal.scheduled_job_runs.

  - missed_clock_in: an accepted assignment on an open or completed shift,
    past start + grace, with no effective clock-in. Urgent; notifies the
    agency.
  - missed_clock_out: clocked in, past end + grace. Urgent; notifies the
    agency AND the worker.
  - Auto-resolution when the facts change:
      * clocked or corrected;
      * assignment not accepted;
      * shift cancelled.
  - Lookback is 7 days; each pass handles at most 5000 rows.
  - Rerunning is a no-op (tested: U).

======================================================================
13. CORRECTION WORKFLOW
======================================================================
Request: request_attendance_correction (the worker, own accepted
assignment).

  - Times are entered in the shift's local time and converted DST-safely.
  - Validity:
      * the time must be in the past and within the shift ± 12 h;
      * clock-out must be after clock-in;
      * clock-in must be before a recorded clock-out.
  - One pending request per type. Rate limit: 20 per person per day.
  - Opens manual_correction_requested and notifies reviewers.
  - Audit records type and reason only: no note text, no times.

Review: review_attendance_correction (attendance.review).

  - Refuses the requester, and the worker whose attendance it is (CH403).
  - Pending requests only (CHT17). The resolution must match the decision.
  - Approval re-checks ordering, then appends a corrected_* event and
    resolves the related exceptions.
  - Rejection appends nothing.
  - The worker is notified of the outcome, and the review is audited.

Terminal states are enforced by a trigger. See
docs/architecture/ATTENDANCE_CORRECTIONS.md.

27. KNOWN LIMITATIONS
======================================================================
  - One work segment per assignment. No breaks or split shifts (the
    schema reserves a segment column).
  - A reviewer cannot enter an alternative time: approval is "as
    requested", or reject and the worker re-requests.
  - Exception review is acknowledge or dismiss only; there are no
    reviewer notes.
  - The agency table covers ≤ 7 days, capped at 500 rows. The scan is
    bounded to 5000 rows per pass with a 7-day lookback.
  - The worker projection spans −7 d to +2 d.
  - No UI yet for viewing raw evidence (the RPC exists: AAL2, audited).
  - Correction notes are free text: they are shown to reviewers and kept
    out of audit.
  - Geofences are circles only; no polygons, no indoor accuracy
    handling.
  - Offline clocking is not supported: nothing is recorded without the
    server.
