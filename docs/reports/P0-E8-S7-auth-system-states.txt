Branch: p0-e8-visual-implementation (base e81933d, S6 committed)
Date: 2026-10-02
Status: complete, uncommitted, awaiting review. Final responsive sweep not started.

======================================================================
1. EXECUTIVE SUMMARY
======================================================================
Every auth surface now uses one P9 canvas (AuthCanvas): Off White with a
flat Mint Mist band, the canonical primary logo centred, and a centred white
card with a Manrope heading. The surfaces are:
  - sign in;
  - sign up;
  - forgot password;
  - reset password;
  - invite;
  - auth error.

System states use one primitive, SystemState: icon tile, the page h1, one
sentence, an optional support reference, and one recovery action. Each state
renders inside the frame that owns the route:
  - workspace shell (Agency / Facility);
  - worker shell;
  - personal frame;
  - auth canvas (unmatched routes and errors outside any frame).

The security pages (Security, Verify it's you, Account) use P6 card language.

No Supabase auth, redirect, invite, recovery, MFA/AAL2, Server Action, RLS,
database, capability or tenancy behaviour changed.

6. PASSWORD RECOVERY
======================================================================
Forgot password and reset password use the same frame. The "Reset link
required" state (no recovery session) is unchanged inside the card.

The hardened token-hash route (/auth/confirm → /reset-password) and the
backend are unchanged. The existing identity tests still prove:
  - the uniform response;
  - the email link;
  - setting a new password;
  - a hosted-style link without `next`;
  - a used link refused (otp_expired);
  - no session → explanation.

The auth error page (/auth/error) is now a P9 SystemState: "We couldn't
verify that link", the safe AUTH_LINK_INVALID message, and two recovery
actions:
  - Sign in;
  - Request a new link.

  - the other organisation's name is not leaked.

======================================================================

(reset):

  Boundary                      Location               Frame
  ----------------------------  ---------------------  ---------------------
  This page could not be        (workspace)/error.tsx  workspace shell
  loaded                                               (restyled)
  This page could not be        (self-service)/        worker shell (new)
  loaded                        error.tsx
  Something went wrong          (personal)/error.tsx   personal frame (new)
  Something went wrong          root error.tsx         auth canvas
  Something went wrong          global-error.tsx       own html; same
                                                       component

Messages are never implementation details. A unit test proves a thrown
message containing "secret" / "line 42" is not shown.

11. LOADING STATES
======================================================================
No loading.tsx was added. It would introduce Suspense boundaries that change
navigation and streaming (and could change 404 status codes for streamed
not-found responses), which the stage forbids for visual polish.

LoadingState (S2 P9 style: icon tile, role=status) remains available and is
shown on the design-system reference.

18. KNOWN VISUAL DIFFERENCES
======================================================================
1. No mint wave artwork: there is no approved asset in public/brand, so the
   canvas uses a flat Mint Mist band (no gradient or improvised artwork).
2. No show-password toggle (not previously supported).
3. The invite names the organisation, not an inviting person (the preview
   has no inviter).
4. No explicit "Access denied" page: privacy-preserving 404s are kept by
   design.
5. No route loading skeletons (§11).
6. The reset-password "link required" state is an ErrorState inside the
   auth card (h2 under the card h1), not a separate full-page state.
