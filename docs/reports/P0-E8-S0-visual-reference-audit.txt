======================================================================
1. EXECUTIVE SUMMARY
======================================================================
I inspected the whole approved library: 15 reference families, 95 files. Every Markdown
spec was read, every HTML file was read (base64 payloads stripped where embedded), and
all 17 images were viewed, including the 2 screenshots that exist only as data URIs
inside index.html. No reference file was changed.

The library is highly regular. 13 of the 15 families are desktop app screens that share
one shell and, in 8 cases, one page skeleton. Nine canonical parents cover every current
Chelth surface:

  P1 App Shell
  P2 Operations Overview
  P3 Operational Workspace, with variants:
       M  monitoring board
       F  finance ledger
       C  calendar
  P4 Record Profile
  P5 Details Drawer
  P6 Settings
  P7 Worker Mobile
  P8 Marketing Hero
  P9 Auth/system states (derived)

All 44 current route files map to a parent. No current screen needs a new mockup.

Only 2 genuine visual gaps exist; both are interaction models the library never shows:
  G1  agency/facility workspaces on phones and tablets;
  G2  workspace switching for accounts with several memberships.

The audit also found 10 reference conflicts that need a product decision, not design
(§F of the map). The most important:
  - the Payroll reference shows payment states (Sent/Paid/Overdue/ACH) that P0-E7
    forbids;
  - finance references use a blue primary instead of brand teal;
  - several sidebar items have no Chelth route (Reports, Notifications centre,
    consolidated Settings, agency Credentials register, agency Staffing Requests);
  - the top-bar global search and notifications bell have no backing feature.

No product behaviour, route, component or schema was changed.

======================================================================
G1  Agency and facility workspaces on phones and tablets.
    Why: all 13 desktop references are desktop-only, and the specs defer to a
      "responsive app-shell pattern" that does not exist.

      - one mobile frame of a P3 screen: navigation, stacked rows, full-height
        details sheet;
      - a tablet rule: drawer as overlay or side-by-side.

G2  Workspace switching and multi-membership.
    Why: Chelth accounts can hold agency, facility and worker memberships at once;
      the references show one workspace and one role.
    Minimum design needed:
      - the user-menu/switcher frame;
      - the /app chooser;
      - how a staff-and-worker user moves between P1 and P7.

Decided derivations, not gaps (optional review): auth (P9), document records (P4),
facility overview (P2), worker offers/breaks/corrections/credentials (P7).

13. RESPONSIVE / MOBILE FINDINGS
======================================================================
22 table regions share one hand-written class string:
  - 8 financial regions are `relative` (fixed in P0-E7-S3);
  - 14 are not, in 12 files: attendance (×3 pages), timesheets (page + entries-table),
    shifts/[id], staffing-requests/[id], workforce, rates, pricing (×2), the
    organisation hub.

Code inspection shows the escaping `sr-only` header — the cause of the measured 817 px
page width in S3 — only on rates and pricing. The S3 report's list (attendance,
timesheets, pricing, rates, shifts, workforce) was based on pattern similarity, not
measurement. This report corrects that: the pattern is unsafe everywhere, but the
confirmed escape is on two pages.

Recommended single fix (S2):
  - a DataTableRegion primitive (`relative overflow-x-auto`, role=region, tabIndex=0,
    required aria-label) adopted by all 22 regions;
  - a Playwright guard asserting documentElement.scrollWidth <= clientWidth at 412 px
    on every table route.

Other responsive observations:
  - inputs must stay 16 px on touch (F5);
  - the worker flow is mobile-first by design (P7);
  - desktop-shell mobile behaviour is G1.
