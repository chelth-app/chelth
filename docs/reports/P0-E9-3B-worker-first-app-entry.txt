1. SUMMARY
----------
/app now sends a Healthcare-Worker-only account to its work instead of the
staff workspace gateway.
- One agency: an immediate redirect to /app/organisations/<id>/my-shifts.
- Several agencies: a worker-only "Choose an agency" page. Each card shows
  the agency name, a "Healthcare Worker" chip and an "Open shifts" action
  that opens that agency's My Shifts.
- There is no "Create a new agency" and no staff workspace list.
- Staff, facility and mixed accounts, and new accounts with no
  memberships, keep the existing gateway unchanged.


2. HOW "WORKER-ONLY" IS DECIDED
-------------------------------
New pure helper: workerOnlyAgencies(memberships), in
src/features/organisations/workspace-navigation.ts.
- Input is the existing listMyMemberships() result (the RLS-filtered rows
  the gateway already loads). There is no new query, RPC or policy.
- Only memberships whose organisation is visible are considered.
- It returns the agencies only when every visible membership meets all of
  these:
  - the organisation is an agency;
  - the membership has at least one role;
  - every role is agency.healthcare_worker.
- Otherwise it returns null and the general gateway renders.
- Examples that keep the gateway:
  - an admin, scheduler or finance user;
  - worker + staff of the same agency;
  - a worker of one agency who is staff of another;
  - worker + facility member;
  - a facility-only member;
  - role-less, empty or hidden-only memberships.
- This is a routing decision only. It grants nothing: each worker page
  still enforces its own capability checks and RLS.


3. REDIRECT RULES (src/app/app/(personal)/page.tsx)
---------------------------------------------------
- Worker-only, one agency, no pending invitation cookie and no notice:
  redirect to that agency's My Shifts.
- Worker-only with a pending invitation (chelth_invite cookie) or a notice
  (?notice=…): the chooser renders instead of redirecting, so the
  "You have a pending invitation — Review invitation" banner and notices
  are never skipped.
  - This preserves the E9-3A invite flow: an existing worker invited by a
    second agency still sees the invitation.
- Worker-only, several agencies: the chooser, with the agencies in
  alphabetical order (as listMyMemberships returns them).
- Everyone else: the unchanged gateway.
- Sign-in still targets /app, so the sign-in destination resolves through
  the same rule (the auth code is unchanged).
- E9-3A post-accept behaviour (accept → My Shifts) is unchanged; it does
  not pass through /app.


4. ACCOUNT, SECURITY, SIGN OUT
------------------------------
- From My Shifts: the WorkerShell "More" sheet (unchanged) links to
  Account, Security and All workspaces, and has Sign out.
  - "All workspaces" → /app. For a single-agency worker this resolves
    back to My Shifts, which is intended: there is nothing else to choose.
- From the chooser: the personal frame navigation (Organisations, Security,
  Account, Sign out) is unchanged.
- /app/account and /app/security never redirect.

10. KNOWN GAPS / NOTES
----------------------
- The personal navigation still labels /app "Organisations", including for
  worker-only accounts. It was left as-is to avoid changing shared
  navigation; a possible copy follow-up is "Agencies" for workers.
- In the WorkerShell More sheet, "All workspaces" for a single-agency
  worker returns to My Shifts (see section 4). This is harmless, but the
  link could be hidden for single-agency workers in a later polish pass.
- Suspended memberships: RLS hides the organisation (organisation = null),
  so they are ignored. Revoked roles are already filtered out. A worker
  whose only membership is suspended therefore gets the general gateway
  with no organisations, as before. No new state handling was added.
