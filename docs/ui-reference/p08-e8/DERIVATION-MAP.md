# Chelth — P0-E8 Visual Derivation Map

Status: P0-E8-S0 audit output (documentation only). Branch `p0-e8-visual-implementation`.

The approved reference library lives in `docs/ui-reference/p08-e8/canonical/` and is
**locked**. This map says which locked reference is the visual parent for every current
Chelth surface, what must be preserved that the references do not show, and where the
references genuinely stop.

Rules this map follows:

- References are never redesigned. Where a reference conflicts with Chelth's product
  boundary, security model or brand authority, the conflict is recorded (§F) — the
  reference is not "fixed" and the product is not changed to match it.
- No functionality is removed because a mockup omits it (§D lists what must survive).
- No new routes are invented. Where a reference shows a screen Chelth does not have
  (e.g. an in-app Notifications centre), it is recorded as _reference without a route_.
- Roles never get separate frontends: one Agency shell, one Facility shell, one Worker
  mobile shell; differences come from capabilities.

## H. Shared fix for mobile table overflow

All 22 table regions hand-roll the same class string. The 8 financial ones were made
`relative` in P0-E7-S3; 14 elsewhere are not. Code inspection shows the escaping
`sr-only` header (the measured 817 px overflow cause) only on **rates** and **pricing**;
attendance, timesheets, shifts and workforce share the unsafe pattern but were not
measured. One fix: a `DataTableRegion` primitive (`relative overflow-x-auto` + `role=region`

- `tabIndex=0` + required `aria-label`) adopted everywhere, plus an E2E guard asserting
  `scrollWidth <= clientWidth` at 412 px for every table route.
